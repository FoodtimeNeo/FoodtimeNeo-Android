# Android 系统提醒

七类提醒共用 `NotificationRepository` 和 `NotificationBatchPoller`，与未读数、目录查询、系统通知适配器分开。未读数仅用于界面角标，不作为新事件判据。提醒设置集中在「我的 → 账号 → 提醒设置」，站内消息不受系统提醒设置影响。

## 旧设置与新事件

- 升级保留旧本机私信开关，向服务器提交一次初始化请求。只有初始 revision=1 可被初始化；已保存的新版选择优先，尤其不能用旧开启覆盖新版关闭。旧关闭也要初始化，防止服务器默认开启造成静默开通。迁移成功才移除旧开关并取消旧 Job 2107。
- 启用时由服务器设置事件基线，不补发开启之前的事件。过期公告、已关闭类别由服务器标记不需系统提醒，站内记录继续保留。
- 每次读取服务器设置；本机只合并相同账号的更高修订号。保存新设置会使在途轮询失效，取消通知与发布共享锁，避免关闭后被慢响应重新发出。
- 从持久化 seq 读取，每批最多 50 条、每次最多 10 页；同类合并为一条通用提示。发布后先保存已显示事件编号，再确认送达和推进游标。回执失败重试只补回执，不重复发布。
- 账号与 API 来源隔离；切号清空旧游标、已显示记录和系统通知。正常会话限制、请求前后账号检查及通知点击后的账号核对分别生效。

## 系统适配与验证边界

Job 2108 使用网络约束、电量非低约束、系统允许的周期及持久化调度，不承诺即时。Android 13+ 单独请求通知权限；拒绝不保存新的开启选择，用户可到系统通知设置恢复。私信沿用原 `private-messages` 通道，尊重用户的通道设置。

锁屏和正文仅显示类别与「打开北交干饭吧查看」，不含私密正文。PendingIntent 显式指向应用，携带账号／类别／安全引用，使用不可变标志；反馈、举报决定、私信及公告分别定位对应入口。受限申诉会话不能借通知进入普通页面。

JVM 检查覆盖稳定事件、合并、回执失败、游标、取消与非法响应；隔离设备 runner 检查真实 NotificationManager、偏好存储、JobScheduler、开关保存和系统 PendingIntent。受控轮询不等于自然息屏、省电或重启调度验收，仍需实机专项。

新客户端依赖后端 `POST users/me/notification-preferences/legacy-message`，发布前须先升级后端。本修复不增加数据库迁移、不改默认角色权限。
