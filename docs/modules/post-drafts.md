# 本机发帖草稿（2026-11-24 更新）

每账号在当前设备只保留一份活动发帖草稿，按账号 UUID 隔离；不建设云同步、多份草稿箱或跨设备同步。

## 存储与恢复

- `PostDraftStore` 将标题、正文、关联菜品 ID、图片文件路径、更新时间和 revision 写入应用私有目录 `filesDir/post-drafts/<accountUuid>/draft.json`；写入使用临时文件、同步与原子替换，失败不先删除旧文件。
- 图片由现有 `PhotoImport` 复制到应用私有目录，草稿只保存可长期读取的本地路径；不保存临时 `content://` URI。
- 编辑过程只更新当前会话，不覆盖已存草稿。关闭、返回、回到首页或切换标签时提供“保存草稿／不保存／继续编辑”；不保存只放弃本次修改，进入前的草稿和配图仍保留。新建后不保存则不落盘；空白草稿不保存。
- 新编辑会话从本机草稿恢复一次；同一会话重绘不反复回填。进程重建优先使用 Activity Bundle 中的会话内容，否则恢复上次明确保存的草稿；缺失图片可移除或重选。
- 只有用户明确保存成功后提示“已保存草稿”；写入失败不退出编辑，保留本次内容与旧有效版本。只有服务器确认发帖成功后才删除已提交草稿。普通退出登录保留已存草稿，原账号重新登录可恢复；注销成功时清理该 UUID 的草稿目录。
- 每个账号最多一份活动草稿；没有跨账号总份数额度，受本机空间限制。保存失败保留当前编辑内容和上一个有效版本，不显示“已保存”。

## 边界

- 发帖仍由服务器审核和权限校验；本机草稿不代表已发布。是否需要学校邮箱由服务器参与策略决定，客户端使用有效角色，恢复门槛后不绕过只读限制。
- 关联菜品仅在当前草稿中保存 ID，发布前仍以服务器目录可见性为准。
- 同一账号在多台设备上各自保存本机草稿，不声称一致或同步。

编辑离开策略由 `PostDraftExit` 管理，存储由 `PostDraftStore` 管理，导航只调用离开守卫。`PhotoImport` 清理前检查已存草稿引用，避免移除本次配图时损坏原稿。
