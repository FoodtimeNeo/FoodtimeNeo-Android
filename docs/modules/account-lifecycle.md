# 账号注销与学校邮箱解绑

Web 入口为“我的 → 账号安全与注销”，Android 为“我的 → 账号 → 账号安全与注销”。普通用户和访客可以注销；已绑定学校邮箱的用户可以解绑。管理员、超级管理员不能注销、绑定或解绑，界面隐藏入口且后端重新检查当前数据库角色。

注销立即生效且不可撤销，通过邮箱验证码认证，不要求密码。已绑定账号向当前学校邮箱发送，未绑定访客向注册邮箱发送。成功发码按账号每天最多一次，固定 UTC+8 00:00 重置；SMTP 明确失败释放本次发码预约，可重试。发送中的并发请求不能重复发邮件。验证码有效期 15 分钟，错误尝试最多 5 次，用途、账号、当前邮箱和密码版本均须匹配；注销与解绑以及注册的验证码不能混用。

注销在同一数据库事务中匿名化原账号、建立邮箱冷却、作废验证码。旧内容保留，作者名称为“已注销用户”、头像清空；旧登录由每次请求的状态和密码版本验证作废。旧身份不可恢复，也不能由管理员重新启用。两个原邮箱冷却一小时后可用于新注册或绑定；新账号是新的 UUID，不继承反馈、历史、私信、关注或其他私有数据。公开贡献与对方已有私信仍引用原匿名身份，不物理删除共享图片文件。注册沿用原来的独立并发和配额，新账号不会继承旧账号的注销发码次数。

解绑验证当前学校邮箱，账号和登录邮箱保留，角色恢复 visitor；已有会话在下一次请求时取得访客权限。学校邮箱冷却一小时后可重新绑定；原登录邮箱仍被该账号使用，不会因解绑变为可注册地址。验证码发送采用独立用途，重发间隔 60 秒。注销和解绑页面均要求知晓影响，并在提交前再次确认。

## 接口

接口前缀 `/api/v1/users/me/account-lifecycle`，需要会话，POST 同时要求 CSRF。

| 方法与路径 | 行为 |
| --- | --- |
| GET 根路径 | 返回 verificationEmail、schoolEmail、canDelete、canUnbind、deletionCodeAvailableAt；再次发送时间为空表示当日未占用 |
| POST /deletion-code | 发送注销验证码，202 返回 expiresAt、nextSendAt、verificationEmail |
| POST /unbind-code | 发送解绑验证码，返回相同结构 |
| POST /delete | `{verificationCode}`；返回 `{deleted:true,emailsReusableAt}`，清理当前会话 |
| POST /unbind | `{verificationCode}`；返回 `{profile,schoolEmailReusableAt}`，客户端同步访客身份 |

重读状态用于跨日、切号或响应不确定后的结果核对。只提交当前账号的验证码，客户端不能指定目标用户或验证邮箱。客户端切号、离页和权限变化后丢弃旧响应；Android 不保存邮箱验证码到草稿或 Activity 状态。

## V46 数据与并发

新增 email_cooldowns（规范化邮箱 SHA-256 键与截止 Instant）和 account_email_actions（每账号每用途的发码预约、HMAC 摘要、发送日、过期时间、密码版本和错误次数）。数据库只保存验证码摘要；SMTP 成功后发布凭据并按实际成功发送时刻记录 UTC+8 日期。无硬件指纹。

账号操作锁、规范化邮箱锁和用户行锁协调注册、绑定与注销，邮箱冷却和身份变化同事务提交。验证码错误的次数独立提交，不能因为抛出业务错误而回滚。users 增加 deleted_at 和 deleted 状态及匿名身份约束；触发器阻止已注销身份恢复。

V46 为新增迁移，V1–V45 保持原样。先更新后端，再更新 Web/Android；本功能不改变正式版本号或发布正式 APK。
