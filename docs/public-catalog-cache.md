# 公开目录按访问缓存（2026-11-23）

## 已确认范围

- Web 和 Android 仅缓存访问到的食堂、档口、菜品、搜索页及对应图片；任何网络均可静默下载。
- 不将数据或图片放入安装包，不全量下载，不在应用启动时预取全目录。社区沿用现有缓存。
- 先校验服务器特征值；未变化读取本机副本，变化只替换当前请求的数据。页面沿用现有加载、刷新和报错方式；校验失败不以旧数据伪装成功。
- 本机副本由同步模块维护，页面只读，所有写入与权限判断仍由服务器执行。
- Web 公共 JSON 与媒体副本共用 100 MiB 上限，按最近访问淘汰。登录、草稿等存储不在淘汰范围。
- 账号、密码、邮箱、私信、个人草稿、反馈、举报、申诉证据、待审内容、管理与审计记录不纳入公共缓存。

## 协议与实现

后端仅对明确标注的公开目录投影返回 `X-Foodtime-Public-Catalog: 1` 与 `ETag`；客户端访问携带 `If-None-Match`。304 无正文，校验本机完整性后复用；200 替换对应副本；401/403/404 不回退旧内容。旧后端没有缓存标记时仍走正常网络读取。

后端 V60 新增事务内目录版本与变更触发器，覆盖目录、图集、审核结果及评分汇总依赖。服务器每次读取一个版本号，版本相同时复用进程内有界查询缓存，避免重新执行目录联表与计数；版本与投影同一数据库快照。输出 ETag 只含公开 data，不含时间戳和请求编号。鉴权和可见性检查不因 304 跳过。

客户端按请求维度保存，不新增全量同步接口；未访问的分页不下载。Android 使用应用私有缓存目录（JSON 32 MiB，图片沿用既有 200 MiB），Web 使用独立 IndexedDB（JSON 和同站目录图片共用 100 MiB）。缓存损坏、存储不可用或空间不足时继续正常网络读取。社区、私有媒体和草稿存储保持各自机制。

图片仅在需要展示时获取，目录同站图片也先校验 ETag；不因读到目录列表而下载全部原图。旧版跨站 HTTPS 图片保持匿名浏览器/既有媒体加载方式，不向跨站发送登录凭据，不将无权限验证的跨站内容纳入新公共缓存。

## 发布与验收

- 先部署含 V60 的后端，再更新客户端；本任务只集成开发分支，不代表授权发布或部署。
- 重点验证：首次访问、重启后 304、改价/改名后更新、停用和删除后不可见、评分/审核变化、回滚、断网和 500、账号切换、损坏文件、容量淘汰及敏感接口排除。
- 自动化结果及准确提交另记于根目录 test/，不得把测试数据当线上联调结果。
