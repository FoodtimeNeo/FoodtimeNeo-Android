# 菜品点评互动与实时评分

本轮按 feature/realtime-dish-ratings、feature/dish-review-likes、feature/dish-review-replies、feature/dish-review-reply-likes 顺序开发并分别合入 dev；数据库和API由同级 Backend 仓库维护。

界面沿用现有纸张卡片、红色评分和深色正文；正文16sp、辅助14sp、触控目标48dp。操作放在对应评论/回复内，保留原导航、评分表单和返回位置；不新增全局导航项。网络操作在worker执行，处理期间禁用重复操作，失败保留输入并就近说明。

实时评分使用 GET /dishes/{id}/rating 的 averageScore/reviewCount；后端在正式点评变化的事务中更新汇总。无评论时均分为NULL；Android不重新平均。每次进入详情通过既有repo.refresh重新请求，画面显示“实时统计”，不轮询每条计数。

一级点评、回复和两类点赞分开存储。主点评重评通过保留ID和互动；删除后新点评不复用旧讨论。回复和点赞不影响评分。后续各功能提交同步维护接口映射及验证记录。

## 一级点评点赞

Review模型增加likeCount/replyCount/likedByMe/counterVersion。新增PUT/DELETE /reviews/{id}/like；按钮在worker提交，直接应用服务端计数和状态，不重新加载整张菜品页。处理期间禁用重复提交，失败就近说明。架构、单元测试、Lint与Debug构建通过；未运行设备验收。

## 点评回复

菜品评论卡片新增“回复 · N”。进入讨论只取20条；加载更多按nextCursor取下一页，不递归拉取整楼。提供回复点评、回复某条、本人确认删除及删除对象占位。写回复表单保留草稿和clientRequestId，失败重试同内容/对象复用标识，成功清除；未审核内容不显示在公开列表。

个人页新增“我的回复 · 审核记录”，每页20条，显示审核状态、原因与原点评删除提示。管理员审核页支持dish-review-reply决策，已通过回复可填写原因后删除。网络操作在worker，加载更多从缓存重绘，避免重新加载第一页。

## 回复点赞（2026-10-20）

PUT/DELETE /review-replies/{id}/like，响应likedByMe/likeCount/counterVersion。公开回复附带同样字段，直接显示；处理中禁用重复操作，失败保留状态并显示错误。只更新回复统计及按钮，不刷新整个菜品页，不改变一级评论计数或菜品评分。

## 嵌入式楼中楼（2026-10-21）

从最新 dev 建立 feature/embedded-review-replies，与 Web 已选方案对齐，采用 Redesign · Preserve。保留纸张、墨棕正文、红色评分章与原导航，视觉变化4、动效2、密度7、素材依赖1、品牌保真10。正文16sp、辅助14sp，轻操作至少48dp；回复浅纸色和安静左分隔使用 Design 的 ALT/BORDER，不新增颜色、字体或依赖。

菜品卡片内直接展开回复，按需读取第一页20条，收起再展开复用当前页；空页也记为已加载，避免重复取数。重新进入详情发现服务端一级点评回复数与缓存不同时，展开状态下刷新该楼，避免旧缓存覆盖新计数。loadReviewReplies 只请求该楼，不重载菜品、图片或评分；刷新重置第一页，更多沿 nextCursor 追加。两类点赞使用同一轻操作组件和服务端版本计数。ReviewActionRow 根据可用宽度换行，不压缩触控区；昵称与内容自然换行。本人删除移入更多菜单并二次确认。

点击写回复或回复某条才展开一个共享编辑器。按楼保存正文、回复对象、编辑/展开状态及重试标识到 Activity Bundle；收起编辑和收起楼层均保留草稿。同一内容/对象失败重试复用 clientRequestId，成功清空草稿并提示审核后公开，不把待审内容插入公开楼层。提交期间禁用正文编辑，阻止切换对象/折叠造成草稿错位。

原 review-replies 和 reply-create 路由保留以兼容已有导航；“我的回复”查看讨论也使用统一的回复面板。审核和个人记录页面仍使用现有接口与权限。后端表、计数、审核与API无需变更。

## 楼层读取队列修复（2026-10-21）

楼层读取使用独立的按资源去重队列，不再占用提交互斥锁。多楼同时恢复会逐一完成；同一楼在重绘中再次订阅时共享一次网络读取，并分别通知当前面板。读取失败可以重试，不阻断其他楼层；页面切换后旧回调不更新新页面，保存状态期间的多个回调在恢复后全部执行。提交、点赞和删除继续使用原写操作互斥与操作恢复机制。

## 一级评论分页（2026-10-21）

菜品详情首屏只请求 `page=1&size=20`，不再通过通用page助手循环读取全部评论。加载更多每次只追加一页，按评论ID去重，失败保持页码和已有内容；末页不再发请求。按页记录服务端total，显示已加载数量；刷新评论重置第一页并重新读取服务端评分汇总。

追加使用原评论卡片实例，保留已展开楼层、编辑器焦点、草稿和点赞状态；点赞响应也写回缓存，避免追加或重绘回退。刷新期间暂时禁用当前评论区输入，失败恢复原内容。个人记录和管理筛选暂沿用既有精确分页方式，不与菜品公开列表混用。
