# 功能范围与开发规则

本轮按用户提供的design-style-web.md、较新FEATURE.pdf、database-design.md及较早需求分析和产品设计PDF开发。附件作为需求资料；用户后续指令与明确确认优先。

已确认的裁决：

- 以较新FEATURE和当前数据库为功能范围，暂不增加点赞、收藏和分类。
- 普通用户为食堂/我的两栏目，管理员增加管理；食堂和档口列表只放封面与名称，菜品列表只放名称和价格。
- 详情使用16:9图片、上传与图册入口、单维评分；评论显示用户ID、分数、文字，不显示头像。
- 个人资料、自己的评论删除、投稿记录、改密和退出，以及管理审核/目录维护/用户管理均接真实接口。
- stall.floor已按用户指令删除，不恢复旧附件字段。
- 图片审核字段和日志关联经用户明确确认，通过Backend V4迁移演进并更新docs/database-design.md。
- 现有学号邮箱与密码规则按用户选择保留，并在接口文档标明额外约定；正式邮箱投递暂跳过，不做假验证码或认证绕过。
- 旧文档的运营员归属、点赞/收藏/分类等未得到当前模型支持，不制造角色、字段或关系。

按dev → feature → dev工作。新分支从最新dev建立；复用分支时把指针同步到最新dev，再修改，禁止把dev合并进旧feature造成交叉树。中文提交、一次非快进合并，保留此前历史。本轮main不发布。

本轮Android功能单元为网络传输、真实数据源/加密会话、实际页面接入与精简，以及集成质量检查。Backend按评论、资料、文件、投稿、审核、目录、用户、图片审核和本地联调分别开发。提交和验证证据见各仓库Git树及verification记录；历史离线模拟验收不等同于当前真实联调。
