# 关注与粉丝

个人页“关注”和“粉丝”进入同一个“我的关系”页面，使用已确认的清晰列表方案。普通用户、管理员、超级管理员都可查看并维护自己的关注关系。

## 页面与交互

- 顶部“关注 · 数量”“粉丝 · 数量”切换两个独立列表；替换当前列表路由，返回一次回到个人页，不因切换堆叠历史。
- 每行展示头像、完整昵称和关系状态。长昵称换行，按钮至少 48dp；没有新增用户主页或搜索入口。
- 关注页显示“已关注”；粉丝页未关注的对象可回关，已关注则显示“互相关注”。取消关注需确认，不会从粉丝列表删除对方。
- 每页 20 人，底部“加载更多”追加记录，结束时显示“已经到底了”。切换列表保留已加载页与各自滚动位置。
- 写入期间禁用重复操作并显示“处理中”；成功只更新当前行、关系及数量，不重载整页。本人关注数通过资料接口校准；资料读取暂不可用时保留已成功的写入结果，根据已知状态更新数量，后续刷新再次校准。
- 首次请求失败显示重试，不作为空列表。刷新、追加和关注操作失败分别显示错误并保留原有数据；显式刷新从第一页重新读取。
- 本设备关注变更后，下一次翻页会重新对齐已加载页，避免 offset 因移除记录而变化，导致下一页漏人。其他设备或其他用户的新变动可通过刷新读取。
- 换号、退出及登录失效清除两份私有列表和关注状态；请求带账号与版本检查，迟到响应不能覆盖新账号或较新列表。

## 接口

所有路径以 `/api/v1` 为前缀，沿用 Cookie/CSRF 和默认 HTTPS 域名。

| 行为 | 请求 |
| --- | --- |
| 当前账号及两种数量 | GET `/users/me/profile` |
| 我的关注 | GET `/users/{当前账号UUID}/following?page=1&size=20` |
| 我的粉丝 | GET `/users/{当前账号UUID}/followers?page=1&size=20` |
| 关注／回关 | PUT `/users/{目标UUID}/follow` |
| 取消关注 | DELETE `/users/{目标UUID}/follow` |

后端没有 `/users/me/following`、`/users/me/followers` 这两个别名。列表使用 `data.items/total/page/size`；行字段为 `id/displayName/avatarUrl/followedByMe`。客户端验证分页字段和内容结构，缺失数据不会被替换为空列表。本轮不改 Backend、Web 或数据库结构。

## 2026-11-02 验证

Android 架构检查、52 项单元测试（含 16 项关注 HTTP 回归）、lint 和 Debug 构建通过。后端现有关注服务 7 项单元测试、5 项真实 HTTP 集成测试通过。

Android API 36.1 模拟器连接本地真实后端，用 45 个关注、125 位粉丝执行 28 项功能验收，覆盖三种角色、超 100 人分页、回关、取消确认、分页位置变化、资料数量、空态、首次失败重试及私有缓存清理。刷新／追加／写入的故障界面通过明确注入 503 检查，正常操作仍访问真实本地后端。小屏、两倍字体、减少动画、系统夜间设置与横屏另外检查；应用沿用现有固定浅色主题。

使用隔离 `.followcheck` 安装包、专用本地数据库 `foodtime_follow_20261102` 与 Redis 命名空间，不写云端。设备测试参数与既有工具约定一致，通过 `FOODTIME_TEST_RUNNER=cn.edu.bjtu.foodtime.presentation.FollowListRunner` 显式运行；测试入口拒绝正式包名和非本地地址。
